# 会话按数据源分组与归档、置顶、删除设计

- 状态：已按评审意见修订，待用户确认书面规格
- 日期：2026-10-03
- 范围：AskDB Web 会话导航、会话元数据 API 与生命周期

## 1. 背景与目标

当前侧边栏把最近会话放在一个全局列表中，每条会话仅显示数据源标签；同一数据源下的会话无法作为一个集合浏览。会话标题与归档状态目前主要保存在浏览器 localStorage，服务端的 `GET /v1/threads` 只返回未过期的活动会话。设置页目前没有归档会话入口。

本设计将一个数据源作为固定分组，支持在分组内创建、浏览多个相互独立的会话；增加服务端权威的置顶、归档和恢复能力；在个人设置中恢复归档会话；保留现有删除影响确认、删除日志及记忆抑制流程。

参考附件只用于理解现有侧栏的视觉语言和会话列表密度。产品范围以用户在本轮确认的需求和决策为准。

## 2. 术语与已确认决策

| 术语 | 定义 |
| --- | --- |
| 会话 | 一个独立的 AskDB 对话，绑定一个数据源 |
| 数据源分组 | 侧栏内按数据源归集的会话列表；V1 不支持用户自建文件夹 |
| 归档 | 从最近会话中隐藏，但保留会话及其数据，允许从个人设置恢复 |
| 置顶 | 在所属数据源分组内排到普通会话之前；归档时保留置顶标记 |
| 删除 | 执行现有的影响确认及删除流程；没有回收站或撤销入口 |

已确认的产品规则：

1. 一个数据源对应一个固定分组，其下的多条会话彼此独立；会话创建后不能改绑到另一个数据源。
2. 会话标题、置顶及归档元数据由服务端作为权威状态。localStorage 仅作为短时缓存，不参与服务端元数据初始化或回写。
3. 归档会话从侧栏最近会话中消失，可在“个人设置 → 已归档会话”中按数据源查找并恢复或删除。
4. 正在打开的会话归档后仍可继续使用；离开后须从设置中的归档列表恢复，才重新出现在最近会话中。
5. 归档暂停会话现有的 30 天无活动到期倒计时。归档时保存剩余秒数，恢复时从该剩余时间继续倒计时。归档期间继续提问会把剩余倒计时重置为 30 天。删除历史备份的保留期沿用现有规则。
6. 置顶状态在归档和恢复后保留，只在原数据源分组中改变排序，不建立额外的全局置顶区。
7. 删除继续使用现有影响确认、幂等删除、删除日志与记忆抑制流程，不提供回收站。
8. 会话所属用户可管理、恢复或删除自己的会话元数据；查看历史和执行查询仍要求当前具备该数据源授权。恢复归档不会重新授予数据源访问权限。

## 3. 侧栏与个人设置交互

### 3.1 最近会话侧栏

- 保留“新建对话”和搜索框。
- 最近会话按数据源分组，组标题显示数据源名称；新会话沿用当前选中的数据源，创建后进入对应分组。
- 每组按置顶优先、最近一次用户提问时间倒序排列；同一排序值以会话 ID 稳定打破平局。
- 搜索覆盖当前视图中的全部会话标题和数据源名称，结果仍保留数据源分组上下文；搜索结果不能局限于已加载页。
- 每条会话菜单提供置顶/取消置顶、归档、删除。标题编辑沿用现有交互，但通过服务端元数据 API 保存，成功后再更新本地缓存。
- 归档后该条立即从最近列表移除；若它正处于打开状态，当前页面不强制跳转或刷新。
- 删除动作展示现有影响摘要，并要求用户显式确认。确认时影响版本已失效则重新加载摘要，不直接删除。
- 对数据源已禁用或授权已撤销的自有会话仍可显示可管理的元数据；打开历史或发起查询时由服务端重新验证授权，并展示明确的不可访问状态。

### 3.2 个人设置中的归档管理

- 在现有个人设置导航中增加“已归档会话”，路径为 `/settings/archived-threads`。
- 归档列表按数据源分组，支持标题与数据源搜索、分页，以及恢复和删除。
- 每项至少显示标题、数据源、归档时间；可显示暂停中的到期倒计时状态。列表不返回对话正文。
- 恢复后清除归档标记并恢复剩余保留时间；它回到原数据源分组，置顶标记不变。
- 删除仍展示既有影响摘要和确认动作。
- 桌面和移动设置导航共享同一导航项定义。

## 4. 数据模型与生命周期

在现有 `agent_conversation_threads` 表上做向后兼容的版本化增量迁移，不更改 `status` 的 `active/deleted/expired` 含义。新增会话元数据：

| 字段 | 类型/默认 | 含义 |
| --- | --- | --- |
| `title` | nullable text | 服务端权威会话标题；空值由应用层展示“新对话” |
| `is_pinned` | boolean/integer，默认 false | 是否在数据源分组内置顶 |
| `archived_at` | nullable timestamp | 非空表示已归档；与 `status` 正交 |
| `retention_remaining_seconds` | nullable integer | 归档时冻结的会话剩余保留秒数 |
| `metadata_revision` | integer，默认 1 | 会话元数据并发版本；数据库迁移为既有服务端会话初始化版本 1 |

会话与数据源关系继续通过现有 `chat_thread_data_sources` 及其 owner 绑定。新增查询按 owner 隔离，不能仅凭猜测出的 `thread_id` 读取或更改元数据。

服务端按 owner 维护单调递增的 `thread_list_revision`，用于校验分页快照。会话创建、删除、归档、恢复、置顶、改标题、用户提问时间变化及数据源名称变化，凡会影响列表成员、搜索结果或排序的操作，都必须递增受影响 owner 的版本。

### 4.1 状态转换

1. 新建：`status=active`、`archived_at=NULL`、`is_pinned=false`、元数据版本从 1 开始；保留期为当前时间加 30 天。
2. 置顶或改标题：只更新对应元数据字段，并在版本匹配时递增 `metadata_revision`。
3. 归档：仅允许 `status=active`、尚未归档且 `expires_at>now` 的会话。在同一事务中校验 owner、版本和状态，设置 `archived_at=now`，保存正数 `expires_at-now` 到 `retention_remaining_seconds`，递增元数据版本。归档任务不改变 `status`。
4. 归档期间用户继续提问：保留 `archived_at`，把冻结秒数重置为 30 天，并更新用户提问时间；仍不出现在最近会话列表。
5. 恢复：仅允许仍为 `status=active` 且冻结剩余秒数大于 0 的归档会话。设置 `archived_at=NULL`，设置 `expires_at=now+retention_remaining_seconds`，清空冻结秒数并递增元数据版本。
6. 到期：只允许未归档且 `status=active` 的会话进入现有过期清理流程。归档期间跳过会话到期清理；独立的删除历史备份保留期不暂停。
7. 删除或过期：沿用现有 tombstone、删除日志、关联内容清理和记忆抑制语义；终态记录不允许恢复或重新导入为活动会话。

所有检查会话保留期限的代码路径必须使用统一的归档感知有效期判断，避免归档会话因旧 `expires_at` 时间戳已到而无法继续使用；恢复时才重新启用从冻结秒数计算出的到期时间。关联业务记忆和候选项仍遵守各自现有有效期，归档不会延长它们独立定义的期限。

## 5. API、BFF 与客户端数据流

Next.js BFF 继续代理 Agent API，浏览器不直连 Agent 服务。所有响应包含 `Cache-Control: no-store`。

### 5.1 会话列表

`GET /api/threads?view=recent|archived&q=...&limit=50&cursor=...`

由 BFF 代理到 `GET /v1/threads`。新客户端必须显式传 `view`：

- `recent`：返回 owner 的未归档、未过期活动会话；先按数据源名称升序、数据源 ID 升序分组，再按置顶优先、最近用户提问时间倒序、会话 ID 升序排序。
- `archived`：只返回 owner 的 `status=active` 且 `archived_at` 非空会话；先按数据源名称升序、数据源 ID 升序分组，再按归档时间倒序、会话 ID 升序排序。终态会话不出现在归档列表中。
- `q` 去除首尾空白后按不区分大小写的子串匹配标题或数据源名称；空值表示不筛选。服务端先对 owner 的完整视图执行搜索，再分页。
- `cursor` 为不透明游标，绑定 owner、视图、规范化后的 `q`、排序位置及该列表的快照版本；默认页大小 50，并设置服务端最大值。创建、删除、归档、恢复、置顶、标题修改、用户提问时间更新或数据源名称变化导致列表成员或顺序变化时，旧游标返回 `409 THREAD_CURSOR_STALE`，客户端清除游标并从第一页刷新。
- 新客户端必须显式传 `view`。因项目尚未上线，不再承诺旧 Web 与新 Agent/BFF 混合运行时的兼容行为。

每项返回 `thread_id`、`title`、`data_source_id`、`data_source_name`、`is_pinned`、`archived_at`、`last_user_turn_at`、`expires_at`、`retention_paused`、`retention_remaining_seconds`、`metadata_revision`。列表不包含对话正文。

### 5.2 元数据与状态操作

- `PATCH /api/threads/{threadId}`：仅支持 `title`、`is_pinned` 和必需的 `expected_metadata_revision`。不接受客户端直接设置 `owner_user_id`、`data_source_id`、`status`、`archived_at` 或到期时间。
- `POST /api/threads/{threadId}/archive`：请求体必须包含 `expected_metadata_revision`；仅允许 owner 归档仍有效的活动会话。
- `POST /api/threads/{threadId}/restore`：请求体必须包含 `expected_metadata_revision`；仅允许 owner 恢复仍有效且冻结剩余时间大于 0 的归档会话。
- `GET /api/threads/{threadId}/deletion-impact` 与 `DELETE /api/threads/{threadId}`：继续使用现有 API、影响版本确认和删除语义。
- `POST /api/threads/states`：客户端批量提交自己缓存中的 thread ID，服务端只返回 owner 视角下每个 ID 的状态（active、archived、deleted、expired 或 unavailable），不返回正文。此接口避免客户端把分页列表中缺失的 ID 误判为删除。

### 5.3 并发与错误

- 元数据写操作使用 `expected_metadata_revision` 做 compare-and-swap；版本不匹配返回 409 和当前元数据投影，客户端刷新该条后提示用户重试。
- 归档与恢复也使用版本校验和数据库事务；状态不满足转换前置条件或 revision 不匹配均返回 409，不保证重复请求幂等。客户端遇到结果不明的网络错误时，先刷新会话状态再决定是否重新操作。
- 删除影响摘要版本过期仍沿用现有 409 错误，客户端重新获取摘要。
- owner 不匹配或会话不存在时统一返回不泄露资源是否存在的 404 投影。数据源授权撤销只使历史读取和查询返回同一 404 投影；owner 的元数据列表、修改、归档、恢复、删除影响查询和删除仍可用。
- 删除完成后客户端清理本地缓存；仅当删除成功或状态接口明确返回删除/过期时才清理远端会话缓存。分页列表的缺席不代表删除。
- 元数据写入或读取失败时保留本地缓存并显示可重试提示；本地缓存不得覆盖服务端状态。遇到 revision 冲突时先刷新服务端投影，再由用户重新发起操作。

## 6. 数据库迁移与上线边界

1. 新建一个版本化 SQLite 迁移，为既有服务端记录增加元数据字段和必要索引；既有行的 `title=NULL`、`is_pinned=false`、`archived_at=NULL`、`metadata_revision=1`。新会话在同一发布版本中以 `metadata_revision=1` 初始化。
2. 本项目尚未上线，不实现旧 Web 兼容层或 localStorage 会话迁移。新版本首次启动时清除旧版会话索引、会话消息、查询结果缓存及未完成的本地历史导入状态；不迁入纯 localStorage 会话及其历史、标题和归档状态，也不清理无关偏好。既有服务端会话及其正文保留，并使用上述元数据默认值。
3. 上线前协同部署 Agent、BFF 和新 Web；新客户端必须通过服务端 API 创建会话并写入元数据，不将本地旧会话合并进列表。
4. 分页列表不得用于推导全量数据中哪些 ID 已删除；使用明确的删除成功结果或批量状态接口做本地缓存对账。

## 7. 权限与隐私

- 所有元数据列表、修改、归档、恢复和删除均要求已认证用户，并以会话 owner 隔离。
- 当前数据源授权只控制会话历史读取及查询执行。归档恢复仅恢复可见性和剩余保留时间，不授予数据源权限。
- 对无数据源授权的会话，允许 owner 管理最小元数据和删除自己的会话；查询历史正文时继续执行现有 grant 检查。
- 列表和批量状态不携带会话正文，也不泄露其他用户的资源存在性。
- 不记录 SQL、对话正文或凭据到归档元数据审计字段。元数据接口设为 no-store，并沿用现有请求体限制和安全错误响应习惯。

## 8. 删除与并发行为

归档、取消置顶、恢复均为带 `expected_metadata_revision` 的状态转换；请求只在当前 revision 与源状态匹配时生效，不提供操作重放幂等保证。客户端收到冲突或结果不明时先刷新状态，再由用户决定后续操作。删除属于破坏性操作，继续沿用两步流程：先获取影响摘要，再把摘要版本交给删除请求。任何会导致影响集合变化的并发更新都使旧摘要失效，必须重新确认。

删除成功后清除会话对话、请求记录及原有删除流程指定的关联数据，记录 tombstone 并投递记忆抑制事件。删除接口保留幂等性；客户端重复提交不产生第二次破坏副作用。已删除或过期的会话不能通过归档列表恢复。

## 9. 验收标准

1. 一个数据源下可以创建和查看多条彼此独立的会话；侧栏按数据源分组，搜索结果仍能看出所属分组。
2. 置顶会话排在所属数据源普通会话前；跨数据源不改变排序；归档后再恢复仍保留置顶状态。
3. 归档会话从最近列表消失，并在个人设置的归档列表中按数据源查到；终态会话不会出现在归档列表；恢复后回到对应侧栏分组。
4. 归档后会话 30 天剩余倒计时被冻结；恢复从归档时剩余秒数继续；归档中继续提问将冻结剩余时间重置为 30 天；已过期或非活动会话不能归档。
5. 正在使用的会话归档后当前页保持可用；已撤销数据源授权时，恢复不会绕过历史和查询授权校验。
6. 删除前显示当前影响摘要并要求确认；摘要已变更时不会悄悄删除，需重新确认。
7. 标题或数据源搜索覆盖全部匹配会话后分页；分页游标绑定 owner、视图、搜索条件及列表快照，列表变化使游标失效并触发从第一页刷新，不会误删本地会话缓存。
8. 两个浏览器同时修改同一会话时，旧版本写入收到冲突，刷新后可继续操作，不会静默覆盖较新的服务端元数据。
9. 新版本首次启动会清除旧版本地会话缓存且不迁移或显示纯 localStorage 会话；既有服务端会话在数据库迁移后使用默认元数据，新 Web 从服务端取得权威状态。数据源授权撤销后，owner 仍可管理元数据和删除，但不能读取历史或执行查询。

## 10. 建议实现顺序

1. SQLite 版本迁移、服务端领域模型与归档感知有效期检查。
2. 列表分页、元数据 CAS、归档/恢复 API、批量本地状态对账 API。
3. Next.js BFF 路由和客户端服务类型；完成服务端 CAS 写入、冲突刷新和分页游标过期恢复。
4. 侧栏数据源分组、每项操作菜单、删除影响确认交互。
5. 个人设置归档列表、恢复/删除交互、状态刷新与错误提示。
6. 上线前协同发布 Agent、BFF 和 Web，验证搜索分页、游标过期恢复及元数据 CAS；localStorage 不承担元数据权威或旧会话迁移职责。

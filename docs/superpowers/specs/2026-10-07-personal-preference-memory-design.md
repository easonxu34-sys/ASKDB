# 个人偏好记忆技术设计

日期：2026-10-07。状态：已依据开发提示词实现代码，静态与关键逻辑验证见交付说明；云服务、浏览器及真实业务查询待用户验收。

产品行为的依据为同目录 `2026-10-07-personal-preference-memory-requirements.md`。下文的存储结构、接口、初始参数和错误处理是技术方案，不应视为用户逐项确认的实现细节。

## 1. 目标与现有基础

第一版完整实现个人开关、聊天明确保存/更新/忘记、跨会话混合召回、A～F 六类记忆、记忆管理页面和三类模型配置。不开启隐式学习，不要求用户填写偏好表单。

现有代码已有认证 Principal、服务端会话与数据源绑定、PostgreSQL 存储、模型目录、BM25、上下文预算和逐轮 Agent 创建。当前 PostgreSQL 迁移器已支持连续增量迁移，不再把它作为需重写的前置项目；新增迁移采用实施时的下一个空闲序号，不修改已经应用的 schema。

主要接入点：

- `api/routes/chat.py`：目前准备认证、会话绑定、runtime lease 和记忆上下文。新增用例通过 application 服务协作，避免继续堆叠编排。
- `application/chat.py`：目前由 Query Gate 判断查询资格，再创建本轮 Agent。明确的记忆管理意图需要独立处理分支。
- `api/chat_stream.py`：保留 SSE 编码、轮次完成/失败和 lease 的 finally 释放。
- `model_settings.py`、`application/model_settings.py`、模型配置路由与 Web 投影：贯通扩展模型类型。
- `application/memory_context.py`：计入本轮个人记忆与工具 schema 的实际上下文成本。
- Web `components/settings/settings-shell.tsx`：新增个人偏好入口，普通用户和管理员都只管理自己的记录。

本阶段保留现有会话必须绑定数据源的产品入口。全局记忆可以在任何合法会话中保存，但不同时新增无数据源聊天模式。

## 2. 已确定的用户体验

- 开关默认关闭；开启后明确说“记住”“以后都这样”“下次也这样”才写入长期记忆。
- 保存成功后简短说明保存了什么及适用范围。写入失败不得生成“已记住”。
- 关闭保留记录但停止聊天保存/更新和个性化读取；当前回答使用原快照，下一轮采用新状态。尚未提交的聊天保存/更新取消，已提交记录保留。关闭时仍可通过聊天明确忘记，不自动开启开关。
- 表达/展示默认全局；步骤/筛选/个人口径/方法默认当前数据源。扩大范围需要用户明确表达。
- 同范围同场景的新要求替代旧要求；不同场景可并存，多条可能适用而影响查询时澄清。
- 默认长期保留，明确期限按期失效。相对查询时间在每次执行时重新解析，绝对日期保持固定。
- 删除来源会话不删除记忆。明确忘记一条直接删除，模糊范围先询问，清空全部一次确认。
- 简单问题不自动展开完整方法；分析问题按需要复用步骤、默认条件及展示方式。

## 3. 统一模型目录

### 3.1 类型与引用

为 `model_profiles` 增加 `model_kind = chat | embedding | rerank`；已有记录迁移为 chat，类型在创建后不可直接转换。供应商与类型独立，百炼使用明确 provider 标识，不能把模型名当作 API 协议。

默认配置只保留一份权威来源：chat 保留现有 `default_profile_id`；新增 embedding/rerank 各自默认值，记忆直接使用这两个默认值，不再维护第二份同义引用。仅 `memory_processing_chat_profile_id` 是独立的记忆处理模型引用。旧接口只投影 chat 默认，新的目录响应返回按类型的默认值；引用均由服务端校验类型、凭据和配置版本。

索引 job/generation 必须能够解析对应配置版本的地址、模型和凭据，不能只保存版本号却读取被覆盖的当前配置。重建期间保留受保护的旧配置版本；仅旧服务可用时才能继续旧空间。撤销旧凭据后改用 BM25，不能用新 Embedding 查询旧向量。

记忆处理模型由管理员显式指定，不随会话模型变动。会话选择器、图表意图解释和所有需要 Chat 模型的调用方必须过滤或拒绝另外两类。模型目录列表仍可展示全部类型。

### 3.2 配置与测试

| 类型 | 特有字段 | 测试方式 |
|---|---|---|
| Chat | 上下文窗口、输出预留、tokenizer | 聊天连通性；被选为记忆处理模型时再验证受限结构化结果 |
| Embedding | 向量维度、协议、配置版本 | 使用非业务测试文本生成向量，检查有限数值、维度与条目顺序 |
| Rerank | 协议、最大候选数等受支持配置 | 测试文本排序，校验候选 index、唯一性、边界和分数 |

百炼候选初始模板采用 `text-embedding-v4`、1024 维和 `qwen3-rerank`，均可在页面改为受支持模型。地域/业务空间影响地址，不硬编码单一租户 URL。Embedding 与 Rerank 分别实现官方协议适配，不共用一个聊天调用器。

配置表单按类型显示字段；Embedding/Rerank 不要求填写聊天输出预留。API Key 沿用服务端 Fernet 加密，仅返回是否配置，不返回密钥。模型测试成功与配置可用状态区分，不把“有 Key”当作调用一定成功。

删除被引用的配置先要求替代项。更改地址、模型或维度增加配置版本；旧索引不与新空间混用。仅轮换密钥且模型空间不变不要求重建向量。

官方接口依据：

- https://help.aliyun.com/zh/model-studio/text-embedding-v4
- https://help.aliyun.com/zh/model-studio/text-rerank-api

实施时需再次核对实际账号的地域、可用模型和接口，不把模板视为已验证可调用。

## 4. 记忆数据模型

以下为建议表名；通过新迁移增加，不覆盖现有业务记忆表。

| 表 | 主要内容 |
|---|---|
| `personal_memory_settings` | owner、enabled、整体 revision、聊天写入 epoch、更新时间 |
| `personal_memories` | 独立 memory ID、owner、类型、范围、触发条件、内容、状态、当前版本、失效时间 |
| `personal_memory_bindings` | 可验证的指标/字段引用、源 revision/digest、绑定状态 |
| `personal_memory_actions` | turn/action 幂等键、动作结果、被操作 memory ID 与版本；不存完整对话或查询结果 |
| `personal_memory_confirmations` | 待澄清或待删除确认的候选 ID/版本、owner/thread 绑定、到期时间 |
| `personal_memory_embeddings` | memory ID/version、generation、模型配置版本、维度、content hash、向量 |
| `personal_memory_index_jobs` | 索引任务、版本、状态、次数、重试时间与有界错误码 |
| `personal_memory_generations` | 当前/构建中索引代际、模型版本、维度及切换状态 |

这些是逻辑职责，第一版不要求一项职责对应一张表：binding/期限/条件放入 memories 的受限 JSONB；action/job/confirmation 可以放入一个带类型的 operations 表。仅对确有独立索引和事务需求的数据拆表，不引入额外队列服务或通用工作流框架。

记忆类型为 `expression`、`display`、`analysis_steps`、`default_filter`、`metric_definition`、`analysis_recipe`。scope 为全局或当前可访问 source。条件使用受限结构：任务类别、指标引用、数据源、时间规则等；展示文本不直接成为可执行条件。

内容由短的原子文本和校验过的结构化 payload 组成。例如筛选包含字段概念、受支持运算符与用户明确提供的非敏感值；方法包含指标、步骤、默认条件、展示偏好，不能包含工具代码或可直接执行的 SQL。多项要求拆成可独立更新的原子记忆，方法再以明确引用组成方案。

状态包括 active、superseded、deleted；是否过期在读取时判断，不依赖 sweeper 恰好执行。旧版本内容不作为普通检索候选。整体 revision 用于本轮快照，单条 version 用于编辑、更新和索引一致性。

绑定状态独立为 pending、valid、stale、unavailable。“描述已保存”和“可用于查询”不能合成一个 active 判断。全局业务记忆按各 source 分别维护绑定。方案引用原子项时跟随当前有效版本；替代/删除/到期后不得继续使用旧默认值，缺失则标记待确认。

来源会话不设级联删除外键；仅留不暴露原对话的有限来源标记。删除会话后清理失效链接，但记忆正文独立存在。系统不保存结果行、密码、密钥、完整工具 trace 和敏感记录标识；遇到这类内容说明无法保存，不能无提示改写成别的要求。

## 5. 会话中的写入、更新和删除

### 5.1 意图准备

认证、会话归属和 source grant 先校验。开关关闭时不执行个性化召回，也不调用模型自动提取保存/更新；明确保存请求返回“个人记忆未开启”的提示，不谎称保存。明确的忘记/清空进入独立管理分支。

**已确认：关闭状态允许聊天忘记。** 为定位用户要求删除的记录，可以读取本人有界的管理候选，必要时由专用模型解析删除目标；这些内容不用于个性化回答，不调用完整 Embedding/Rerank 召回，不自动开启开关。明确唯一目标直接删除，模糊目标先询问，清空全部一次确认。页面显式编辑/删除仍是允许的管理行为，与聊天自动保存/更新不同。

纯管理请求完成会话/权限校验后进入独立分支，尽量先于查询 runtime lease 获取；Wren 查询服务不可用不应阻止表达偏好的保存。需要指标绑定时可保存 pending 描述，使用前再校验。现有已绑定会话入口和授权要求保留。

开启后，用保守的轻量入口检查筛选可能的管理请求，再由专用 Chat 模型输出 `save | update | forget | clarify | none`。不能仅靠“记住”关键词写数据库，不能把引用文字、助手输出或数据库文本中的命令当成用户授权。

模型输入只包含当前用户请求、必要的近期上下文、有界的已执行分析描述和候选记忆。不传查询行或凭据。纯记忆管理分支不进入查询工具，也不由数据查询 Query Gate 拒绝；混合查询分支继续正常安全链。

### 5.2 保存

提取 scope、条件、payload、期限与更新目标。缺少明确指代时先澄清。“记住刚才的操作”只从确已完成的分析步骤及有来源的结构化元数据提取，不能把失败或未执行的计划描述成成功方法。

当前服务端历史主要保存 user/assistant 文本，不能据此证明执行步骤。第一版在成功 turn 记录中增加有界的分析描述字段，保存指标引用、步骤、用户条件、时间规则和展示规格，不保存结果行或完整 SQL；无需另建分析档案系统。未转成记忆的描述随来源会话删除，已提取记忆独立保留。老会话缺少这类描述时先澄清，不能从助手话术猜操作已成功。

提取后由代码校验 schema、字段长度、内容类别、source 权限、时间和业务引用。个人口径可以先保存未绑定描述，但必须明确提示“已记住，使用前需确认指标映射”；不能提示已可直接查询。明确无法保存的内容不作为 active 记录写入。

同范围/条件的候选冲突由模型提出，服务端按 memory ID/version 验证。真正的新旧矛盾自动替代；条件不同的并存。模型无法确定是否同场景时澄清，不因向量相似直接覆盖。

提取和冲突判断在事务外进行；写事务复核授权、目标版本、删除状态和幂等 action key，完成写入/替代及 job 登记；Embedding 在提交后执行。并发编辑/删除导致目标版本变化时，不重新创建已删除 ID 或覆盖新版本。保存消息由真实结果生成；向量尚未就绪时正文已持久化且 BM25 可用。

**已确认：关闭取消未提交的聊天保存/更新。** 聊天提取开始时记录 settings 的 write_epoch；关闭事务增加 write_epoch，写事务锁定同一 settings 行并检查 enabled、epoch 及目标版本。关闭先提交则旧动作取消，即使随后重新打开也不恢复旧动作；保存先提交则保留记录。只取消记忆写入，不取消当前回答，不声称已记住。现有记录的索引维护可继续，因为它不创建新的用户记忆。关闭不阻止明确忘记或页面显式管理。

混合“查询并记住方法”请求只在相关操作成功后保存方法。查询失败不保存未完成方法；保存失败不抹掉已成功查询结果，分别说明结果与记忆状态。同一 turn 重试不能重复写入或重复更新版本。

### 5.3 忘记与清空

明确唯一目标直接忘记；多个匹配或“忘记之前的设置”先返回候选。清空全部创建一次性确认 token，绑定 owner、操作范围及 revision，防止一句普通“可以”或过期确认误删其他记录。

删除先写持久 suppression/tombstone，再更新权威记录并清理内容/索引/任务。删除恢复机制接入独立删除日志参与者，保留不含正文的必要标识，恢复备份必须先重放 tombstone。不能仅删除向量而保留 active 正文，也不能让迟到索引任务重新启用 deleted/superseded 版本。

现有 JournalEvent 必带 source_id，需增加能表达 owner 和 global/source 范围的版本化个人事件，不能把全局记忆假绑业务数据源。日志已持久化但数据库清理失败时进入 removal_pending，读取/写入入口检查删除屏障，后台重放清理；失败或迟到任务不得复活正文。更新也要保证恢复旧备份时不会重新启用被替代版本；复用现有日志能力，不另建恢复平台。

清空只影响该 owner 的个人记忆，不影响开关值、会话、业务规则或其他账号。

## 6. 跨会话检索与有效配置解析

每轮认证后在短事务中读取开关、整体 revision 和有界的有效记忆集合；开启才创建本轮不可变快照。全局记忆和当前 source 记忆由 owner/source 权限联合过滤。不得静默截断可能影响默认范围和口径的集合；超过工程容量时明确提示容量问题。

先读取固定表达/展示配置以及可能改变查询语义的结构化默认范围、个人口径索引。后两类不能只依赖向量 Top-K，否则召回漏失可能让查询变成全国或正式口径。

可选场景文本执行 BM25 与云 Embedding/pgvector 两路召回，再以本地 RRF 融合，用云 Rerank 排序，最后核验候选是否属于本轮已授权快照、版本是否对应、期限和条件是否适用。候选文本在云调用之前完成 owner/source 过滤；排序结果从来不构成授权。正在运行轮次继续使用原快照，不因并发编辑替换成下一轮的新记忆；索引缺失时用快照文本做 BM25。账户/source 撤权仍遵循现有服务端授权与抑制契约。

初始工程参数建议每路最多 20 条、Rerank 最多 20 条、可选上下文最多 5 条，固定配置和必需语义绑定另行计算；参数需评测，不是已确认的产品常量。RRF 分数不当成“匹配可信度”，不保证填满 Top-K。

范围/口径/方法条件明确才采用。多个有冲突的场景都可能匹配时，返回有界选项澄清。服务故障、真正无匹配和条件不明确是不同状态，不能统一为“没有记忆”。

覆盖顺序为：安全与权限/确定性执行约束 > 当前明确要求 > 当前数据源的适用个人记忆 > 全局适用个人记忆 > 产品默认。正式数据源指标的原定义不会因个人别名修改；个人口径在其适用范围内选择不同的明确指标解释。

默认筛选和个人口径在查询前进入已验证的本轮请求解释，并在回答/展示中明确标注。所有实际查询仍执行 `validate_read_query → dry_plan → dry_run → query`。不得静默补猜字段、公式、币种或单位。

仅注入提示词不能证明实际 SQL 遵循了记忆。第一版将已绑定的筛选/指标映射显式传入本轮工具上下文，复用现有 SQLGlot 与计划结果对能明确识别的引用/条件核对；无法确定时澄清，不声称已应用。不同分析步骤按其实际需要使用条件，不全局强塞筛选。不要新增通用 SQL 等价证明器、发布门禁或额外人工审核。真实语义正确性由用户按样例验收。

## 7. 个人业务定义与 Wren 的衔接

“收入指实收金额”是用户私有名称到明确指标的映射，不是覆盖共享 MDL 的代码或指令。记忆处理服务给出候选绑定，绑定校验组件只允许当前授权 source 中可验证的指标、字段和受控表达式；无映射或含义不唯一时 CLARIFY。

绑定至少包含 source、当前 revision/digest 和目标指标引用。活动语义版本变化后重新验证，不能把旧绑定自动当成新版本事实。跨 source 扩大的个人定义也须在各 source 重新绑定。

Query Gate 接收的是已校验的私有指标映射和请求解释，而非任意个人记忆正文；普通表达偏好不参与业务资格判断。共享 runtime、系统政策和源模型都不写入用户私有内容。

方法中的每步按当前请求需要展开，在受控工具入口重新检查权限、聚合安全和图表有效性。默认折线/饼图等是建议，不绕过现有形状和完整性检查。未知源单位保留原显示，单位转换仅作用于展示，不改原始结果。

## 8. 索引生命周期

权威记录与 job 在同一事务提交；后台工作者领取任务后在事务外调用 Embedding，再有条件地提交该版本向量。处理前后检查删除状态、版本、content hash、generation 和模型配置版本，失败有界退避重试。

第一版按用户与代际过滤后使用 pgvector 精确近邻搜索；不为每个用户维护 HNSW，也不为追求 ANN 性能牺牲严格过滤。不同维度可用无固定维度 vector 列记录，但每次搜索先物化当前代际的过滤集合、校验维度，再计算距离。待数据量和并发实测证明需要时添加 ANN 索引。

Embedding 空间变化时创建新 generation，批量重建且同步接收新写入；验证覆盖和版本追平后切换 active generation。构建失败继续旧空间检索或 BM25，不能用新模型查询旧向量。Rerank 模型切换不要求重建 Embedding。

## 9. 故障、上下文与运行轮次

| 情况 | 处理 |
|---|---|
| Rerank 超时/无效结构 | 使用 RRF 排序，保留状态/版本和条件校验 |
| Embedding 超时/索引缺失 | 使用结构化记录与 BM25 |
| 专用模型不可用或输出非法 | 不保存、不覆盖、不猜删除；说明失败，普通查询独立处理 |
| 降级后仍无法确认默认范围/个人口径 | 提示记忆不可用或待澄清；用户明确同意后才按当前问题继续 |
| 个人记录读取故障 | 若本轮开关开启，不静默当成无记忆；提示重试/明确不使用记忆继续 |
| 列表/编辑失败 | 保留草稿，禁止成功提示 |
| 并发修改 | CAS 冲突，不静默覆盖 |

开关本身读取失败时不能推断为关闭，也不能仅靠浏览器缓存决定是否检索。返回明确的记忆状态不可用，允许本轮明确选择不使用记忆；这一选择不永久修改开关。用户同意降级只豁免本轮无法读取的个人默认值，绝不豁免权限或当前指标仍不明确的问题。

运行轮次的回答读取快照在开始时确定，后续修改/关闭/删除对回答从下一轮生效；聊天保存/更新则遵循提交前 enabled/write_epoch 检查，两者不是同一个生效边界。不能把用户快照缓存进 RuntimeManager 的共享模型 runtime。快照随 turn 完成、失败或取消释放。

个人记忆计入上下文预算。先保证安全政策、当前请求、必要的已确认语义绑定和工具 schema；可选表达/方法可裁剪。必要范围/口径放不下时提示上下文不足，不静默丢弃后执行更宽查询。

保留 chat_stream 既有完成/失败标记和 lease finally 释放；新增纯管理分支也必须完整结束 turn。历史消息是会话内容，关掉长期记忆不等于删除当前会话已经出现的文字；禁止通过重新检索历史绕过关闭开关。

## 10. API、页面与应用事件

个人 API 均基于 Principal，不接收可伪造的 owner：

| API | 用途 |
|---|---|
| `GET/PATCH /v1/me/memory-settings` | 开关和配置 revision，PATCH 使用 expected_revision |
| `GET /v1/me/memories` | 按类型/source/状态分页列出本人记录 |
| `PATCH /v1/me/memories/{id}` | 编辑；结构化/文本变更经校验和必要重新提取，不任意执行正文 |
| `DELETE /v1/me/memories/{id}` | 带版本删除明确的一条 |
| `POST /v1/me/memories/clear-preview` | 返回清空影响与短期确认 token |
| `POST /v1/me/memories/clear` | 校验 token、范围和 revision 后执行 |

自然语言动作使用现有认证 `/v1/chat`。确认采用明确协议：增加可选 `personal_memory_response`，携带服务端签发的 request_id 和 choice_id；页面按钮发送该字段。纯文字“是”仅在该 owner/thread 存在唯一且未过期的待处理项时关联；多个待处理项则询问具体对象，不由模型自由猜测。服务端再校验 source、目标版本和有效期。

动作幂等状态和待确认项持久化，网络断开重试不重复保存/删除。历史刷新可恢复有界状态和有效的确认按钮；已删除记忆只显示动作状态与必要 ID，不重新投影正文。操作完成后确认请求一次性消费，过期或版本变动提示重新操作。个人页列表使用 owner/filter 绑定的有界分页游标，API 设请求大小/条数上限，旧会话协议不支持确认字段时不执行破坏性默认动作。

个人页面 `/settings/preferences`：开关、记忆列表、scope/期限/状态、编辑删除、清空和失败重试；说明“当前回答继续，下一轮不再使用；尚未保存的记忆操作将取消”。编辑/删除提示对回答从下一轮生效。关闭仍能查看/管理保留记录。管理员页管理模型服务引用和索引状态，不能因此默认获得其他用户的个人记忆列表。

所有 BFF 走同源，复用 Cookie/CSRF/no-store，完整投影 schema 和错误映射。选择型下拉统一 ComposerSelect，沿用现有响应式设置布局。

应用事件建议为 `personal_memory_action`、`personal_memory_usage`、`personal_memory_clarification`，由 application 生成有界 payload，chat_stream 编码，Web/BFF 同步适配。动作结果只含安全摘要/ID/状态；不发送模型提取 trace、提示词或原工具结果。

使用提示区分“已提供给模型的偏好”和确定性应用的范围、指标映射/展示配置。不能把注入上下文描述成模型百分百遵循。没有使用记忆时不显示空状态卡。

错误码覆盖 disabled、processing unavailable、invalid content、scope unavailable、revision conflict、confirmation stale、retrieval degraded 和 index pending；HTTP、SSE 应用状态分别按入口映射，不能把所有问题包装为聊天 409。

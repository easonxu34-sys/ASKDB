# 个人偏好记忆：需求讨论记录

日期：2026-10-07。

本文件记录当前会话中用户明确确认的产品行为。不是实现完成报告，也不代表数据库迁移或在线记忆效果已验收。本文不修改现有业务记忆设计；两者衔接需在技术设计中具体定义。

## 一、目标与入口

- 管理员和普通用户都有自己的个人偏好记忆开关；记忆按已认证用户隔离。
- 管理员和普通用户的开关均默认关闭，由本人开启。
- 开关打开后，支持会话中明确要求保存，并在后续会话自动读取相关记忆。
- 仅明确表达长期记忆意图时保存，如“记住”“以后都这样”“下次也这样”。普通交流不自动沉淀。
- 页面提供开关、记忆列表、内容与适用范围查看、逐条编辑和删除。日常不要求填写表单。
- 关闭开关停止聊天保存/更新和用于个性化回答的读取，但保留已有记忆；重新打开后恢复使用。关闭时仍允许通过聊天明确忘记，属于管理操作，不自动开启开关；模糊删除和清空继续执行确认规则。
- 当前轮次使用开始时读取的记忆快照；关闭、修改或删除对回答的影响从下一轮生效。关闭时取消尚未提交的聊天保存/更新，已经提交的记忆保留，页面明确说明读取与写入的区别。

## 二、支持的内容与应用行为

| 类型 | 已确认的行为 |
|---|---|
| 表达偏好 | 自动应用称呼、语言、回答组织等相关偏好 |
| 展示偏好 | 数据条件允许时应用单位、图表等展示偏好 |
| 操作习惯 | 根据本次问题需要采用记住的分析步骤 |
| 常用范围 | 自动采用默认筛选范围，并明确显示采用的范围；当前明确要求优先 |
| 个人业务定义 | 优先采用个人口径，并明确显示；共享数据源定义不因此修改 |
| 分析方法 | 保存步骤、默认条件和展示方式，根据当前问题及最新数据重新执行 |

- 简单问题直接回答；例如询问销售额不自动执行趋势与地区拆分。明确要求分析时，才按需要使用完整方法。
- 相对时间保留其规则，在下次执行时按当前日期重新计算；明确指定的日期保留为固定日期。
- 不把旧查询结果当成当前数据，不因记忆绕过权限、语义校验或查询安全。
- 个人业务定义须映射到当前数据源可验证的指标、字段和计算含义；无法确定时澄清，不猜公式。

## 三、范围与生命周期

- 表达和展示偏好默认跨数据源。
- 分析步骤、默认筛选、个人业务定义和分析方法默认绑定保存时的数据源。
- 用户明确要求所有数据源适用时才扩大范围；新数据源中使用仍须校验适用性。
- 同一适用范围内，新记忆自动替换冲突的旧记忆，并简短告知；不同场景可并存。
- 记忆独立于来源会话保留，删除会话不删除已保存记忆。
- 默认长期有效，直到修改或删除。用户明确指定期限时，到期停止使用。
- 明确指向一条记忆的“忘记”直接删除；指代或范围模糊时列出候选并询问。
- 清空全部个人记忆需要一次确认。
- 只有持久化成功后才能告知“已记住”。
- 匹配明确时自动应用；多条记忆都可能适用且会影响指标、筛选范围或分析步骤时，先简短澄清。
- 云端检索失败时先降级到结构化记录和 BM25；仍无法确认可能影响查询的默认范围或个人口径时，提示记忆不可用，询问是否按当前问题继续。不得无提示扩大查询范围。

## 四、已确认的技术方向

- 第一版包含 PostgreSQL、pgvector、关键词 BM25、云 Embedding、本地 RRF 和云 Rerank。
- Embedding 和 Rerank 首版按阿里云百炼／通义千问服务接入；具体模型和地址由管理员配置。
- Web 现有模型配置新增 Chat、Embedding、Rerank 类型，统一页面管理；不采用 Agent `.env` 作为这两类服务的业务配置入口。
- 记忆提取、冲突判断和更新使用管理员指定的专用 Chat 模型，不随当前会话模型切换。
- 会话选择器只展示 Chat 配置；不同类型的默认配置和记忆处理模型引用须分别管理。

# 自然语言图表编辑设计

> 当前状态：自然语言修改图表功能已于 2026-10-06 移除。本文保留为历史设计记录；当前图表修改使用手动编辑器，查询仍可直接在聊天中提出。

> 2026-10-05 增量更新：模型输出协议、配置归一化、一次安全纠错和预览确认以 [图表编辑意图精简与统一编译设计](2026-10-05-chart-edit-intent-compiler-design.md) 为准。下文 `ChartEditIntent` 是程序生成的内部/API 响应，不再直接作为模型输出 schema。

## 目标

用户可以用自然语言修改现有图表，安全的展示层改动先进入预览，确认应用后生效，并能看到明确的变更摘要和撤销操作。仅对需要更多数据或新查询的变换发起查询，并与展示层编辑分开处理。

## 产品行为

### 展示层编辑

- 在现有图表编辑入口旁提供醒目的自然语言输入框。
- 支持的例子包括：切换图表类型或方向、选择结果中已有字段、对返回行排序、修改标题或标签、在源单位已知时设置显示单位，以及从固定图表配色中选择颜色。
- 展示层编辑通过验证后进入现有编辑对话框预览；取消不保存，应用后显示简明摘要和“撤销”操作。
- 字段、单位或图表类型存在歧义或不兼容时，必须询问或显示校验消息，不得静默猜测。
- 手动编辑器的“应用”和自然语言编辑必须调用同一个经过校验的图表视图持久化操作。

### 当前结果内的操作

- 首个版本支持对当前结果已返回的行执行 Top N。
- 界面明确标出范围是“当前返回结果”。只要存在任一截断信号，就同时提示排名仅覆盖已返回行，不代表全量数据排名。
- 用户只说“前 10 名”但没有说明范围时，询问其指当前结果还是全量数据查询。

### 需要查询的操作

- 首个版本中，数据库筛选、全量 Top N、按月聚合和同比分析都需要新查询。
- 执行前向用户展示待执行操作及固定文案说明，由用户明确确认后再发起。
- 混合指令中的展示层编辑先与查询暂存；只有新结果和图表均成功产生后，才将仍兼容的暂存编辑应用到新图表。查询失败时旧图表保持原样。
- 已确认的查询必须经现有认证聊天和查询安全链路执行。图表编辑解释器本身不能执行工具或 SQL。

## 架构

1. Web 将原始指令和有界的图表上下文发送到专用的图表编辑意图解释端点。上下文包括当前视图、源结果 ID、可用字段名/类型、已返回行数和截断状态；不包含查询行、SQL 或工具输出。自然语言编辑区提供本次编辑专用的模型选择，默认沿用当前会话模型；会话未指定模型时使用模型目录默认项，并通过 `model_profile_id` 显式发送。该选择不写入会话模型偏好。所有客户端字段都只是未受信任的意图解释上下文，不能作为授权依据。
2. Agent 端点要求线程已存在、归当前服务端管理且已绑定数据源。端点以当前认证主体读取线程，从服务端绑定中派生数据源 ID，重新检查当前授权，并通过 `RuntimeManager` 解析所选模型配置。请求中没有 `data_source_id`，端点不得创建线程或重绑数据源。解释器使用已获取快照上的模型，并在成功、错误、超时或取消时都通过 `finally` 释放 `RuntimeLease`。
3. `ChartEditInterpreter` 使用共享 runtime model 和严格结构化输出 schema。它不绑定 Wren 工具、图表渲染工具，不接收查询行或 SQL，也没有工具调用循环。当前模型封装是通用的 `init_chat_model`，模型配置探测只验证普通调用，因此必须逐个验证启用中的 provider/model 组合是否支持结构化输出。兼容性按 profile 的实际 schema 调用判定，不能按 provider 名称推断；选择器仅列出可用 profile，若所选模型拒绝结构化输出，保留安全错误供用户切换后重试。解释器应延迟创建和调用，避免不兼容影响普通 `/v1/chat`。禁止降级为自由文本或自行解析 JSON，图表不得变更。
4. Web 根据实际查询产物和现有 `validateChartView` 规则再次校验意图。有效展示补丁通过与手动编辑器相同的操作提交。
5. 对需要查询的意图，界面展示操作、固定文案说明，以及确认时将发送的完整自然语言聊天消息。意图中不得包含模型生成的查询文本或 SQL。确认后，将用户原始指令加上明确的图表请求前缀（例如 `请按以下需求查询并生成图表：…`），并把界面预览过的这条消息提交到现有 `/api/chat` → `/v1/chat` 链路，确保现有图表请求检测器能识别。后续查询继续使用当前会话模型，不继承本次图表解释的临时模型选择。意图解释请求本身不得发起查询。

现有查询 Agent 保持不变。不要另建带工具的 `create_agent` 来编辑图表，也不要在 `build_graph`/`AgentRuntime` 中急切构造解释器。复用 `lease.snapshot.graph.model` 上的模型，通过独立的 application 用例、路由、提示词和 schema 隔离图表编辑逻辑。

## 开源方案复用评估（2026-10-05）

- [VisActor/VMind](https://github.com/VisActor/VMind) 与自然语言图表生成/编辑最接近，但 README 的“Dialog-based editing”仍标为开发中；示例输出 VChart spec 并使用 VChart 渲染，不能直接替换本项目的 `EChartsChartArtifact`/`ChartViewConfiguration`。其 API 以数据集作为图表生成输入，且示例允许在模型请求 header 中配置 API key；直接嵌入会与本方案不向解释模型发送查询行、密钥留在服务端的边界冲突。因此仅借鉴产品交互和结构化图表意图，不作为可直接接入的运行时依赖。
- [nyanp/chat2plot](https://github.com/nyanp/chat2plot) 支持以声明式 JSON 配置生成图表、后续自然语言细化，并说明模型不生成可执行代码或 SQL；但其运行时围绕 Python DataFrame 与 Plotly/Altair，输出 schema 也不是本项目的 ECharts view/持久化契约。可参考其结构化输出思路，不直接替换前端图表编辑器。
- [microsoft/LIDA](https://github.com/microsoft/lida) 有自然语言编辑能力，但其 README 明确采用生成并执行可视化代码的模式；这不符合本项目不接受模型生成/执行代码的安全约束，不应接入该执行路径。

结论：目前没有发现能直接复用、同时保留本项目认证、线程/数据源授权、查询安全门禁、ECharts 数据产物和本地视图历史模型的成熟即插即用组件。V1 沿用现有图表模型与 renderer，只复用上述项目可借鉴的声明式意图模式；引入依赖前需要重新审查其 API、数据传输、许可和维护状态。

## 意图契约

Agent 返回严格对象，包含：

- `status`：`apply`、`query_required` 或 `clarify`。
- `patch`：可选的 `ChartViewConfiguration` 允许字段子集。
- `current_result_operation`：可选对象 `{ kind: "top_n", field, count, direction, scope: "current_result" }`。`count` 为 1 至 100 的整数，`direction` 为 `asc` 或 `desc`。Web 以确定性方式将其映射到 `ChartViewConfiguration.current_result_top_n` 和相同补丁中的度量排序。
- `category_color_operations`：可选的类别配色操作列表，每项为 `{ category_label: string, color: ChartPaletteToken }`，最多八项。仅用于饼图；Web 必须根据当前源结果将标签解析为唯一的、类型化的类别值，再转换成持久化键。类别值和类别列表不发送给解释端点。
- `query_proposal`：可选的允许操作枚举，只能是 `database_filter`、`full_data_top_n`、`aggregation` 或 `period_comparison`。界面根据本地固定文案生成原因；响应不得含模型编写的原因、查询文本或 SQL。确认时使用前文所述的原始用户指令。
- `clarification`：可选对象 `{ code }`，其中 code 只能是 `top_n_scope_required`、`top_n_metric_required`、`source_unit_required`、`field_not_in_result`、`category_not_in_result`、`category_ambiguous`、`conflicting_category_color`、`chart_type_incompatible`、`conflicting_sort` 或 `operation_unsupported`。Web 根据本地固定文案和已校验的结果字段/类别生成问题及选项；模型不得编写直接展示给用户的澄清文本。

`patch` 仅限明确允许的 `ChartViewConfiguration` 展示字段以及有界的单位/度量配色 token；不得直接设置 `source_result_id`、原始 ECharts 选项、`current_result_top_n` 或饼图类别颜色（Top N 和饼图类别颜色分别只能通过各自的类型化操作设置）。标量和列表字段用新值替换旧值；嵌套的标签/格式/度量颜色映射只合并本次明确指定的字段键，保留未提及的设置。状态必须满足以下约束：`apply` 至少包含非空补丁或当前结果/类别配色操作，且不得包含查询/澄清字段；`query_required` 必须包含 `query_proposal`，可携带待暂存的展示操作；`clarify` 必须包含澄清代码，且不得包含补丁、当前结果/类别配色操作或查询操作。成功摘要由 Web 根据校验后的变更前后视图确定性生成，不得将模型文本作为摘要、查询原因或澄清问题展示。类别配色操作最多八项，每个 `category_label` 限制为 128 字符，重复类别及相互冲突的颜色必须在提交前拒绝或澄清。

服务端拒绝未知字段、无效枚举、超长文本、缺失状态必需字段及不一致组合。请求体最多 64 KiB，指令最多 2,048 字符，最多 100 列；字段名最多 128 字符、类型名 64 字符、标题 120 字符、字段标签 80 字符，类别操作标签最多 128 字符且每个响应最多八项。名称、标签和指令均视为不可信数据，不能插入为系统指令。确定性策略同时接收原始指令、类型化模型意图和有界上下文；由策略代码（而非模型文本）判定操作是本地支持、存在歧义还是需要查询，并给出允许的提议操作。Web 在保存或查询前，再根据实际图表和查询结果执行一次校验。类 SQL 或模型生成内容不得成为确认时发送的聊天消息或界面提议原因。

对于混合展示/查询指令，`status=query_required`；补丁及支持的当前结果/类别配色操作保存在本次请求的 UI 暂存状态中，并关联旧结果 ID 和确认后的聊天 turn ID。只有确认后的 turn 成功完成，且成功查询产物和图表产物具有相同的新 `source_result_id`，并且所有暂存字段/类别标签都通过针对新结果的校验后，才提交暂存编辑。失败、取消、结果不明确或不兼容时丢弃全部暂存编辑。新结果成功前绝不能提前修改旧图表。

## 共用提交和撤销状态

- 一个 Web 函数负责提交手动编辑和自然语言编辑的有效配置。其作用域明确包含用户 ID、远端 thread ID、history/turn ID 和源结果 ID；提交前验证指定 turn 中的查询与图表产物仍存在，并验证已存视图仍与调用方的 `before` 视图相同。
- 当前 override 和撤销记录须在同一次、按 turn 隔离的 artifact-cache 写入中持久化。为新增视图字段/历史记录升级 `ChartViewOverride` schema 版本，并继续读取旧版 v1 override，将其视图载入且历史初始化为空。更新回放解析逻辑，把历史提供给 UI；同时更新 `chartViewsEqual` 比较新增视图字段，避免 Top N 或颜色变更被视为相同。
- 每次成功提交都在有界历史中保存旧视图、新视图、摘要、来源、源结果 ID 和时间戳，然后在同一次写入中替换当前 override。
- 撤销仅恢复同一源结果的上一个视图，不会反向撤销数据库查询。
- 每个图表最多保留 20 条撤销记录，并存放在现有有界本地 artifact cache 中。写入失败或超出容量时，存储中的 override/历史和界面状态都保持不变。结果过期/淘汰，或查询/图表产物缺失/不兼容时，该图表不可编辑或撤销；不得将记录应用到其他结果，也不得静默合成缺失产物。
- “撤销上次编辑”和“恢复 AI 推荐”是两个不同操作。
- 历史保存在浏览器本地，并遵守其所依赖的查询/图表产物相同的保留和淘汰边界。

## 数据操作策略

- 当字段存在于源结果中时，展示字段修改和字段选择属于本地操作。
- 排序和 Top N 仅作用于前 1,000 条已返回行。V1 Top N 支持柱状图；饼图仅当现有饼图规则已满足（结果未截断且有效类别不超过八个）时支持；折线图不支持 Top N，以保留时间顺序。Top N 限制为 1–100 行，且只能使用当前已选中、可见的数值度量；可用行少于 N 时展示所有符合条件的行。若度量缺失、隐藏或有歧义，应澄清，不得擅自添加度量。“前 N”降序排名，“末 N”升序排名。数值相同时保留原始行顺序。Top N 生效期间，其度量和方向同时决定展示排序；若用户另行指定冲突排序，应澄清。手动改用其他排序、切换折线图，或字段选择移除/隐藏排名字段时，在同一次提交中清除 Top N，并在摘要中说明清除。不得将 Top N 描述成完整数据库排名。
- 若产物标记截断、返回行数超过 1,000，或报告总行数大于实际返回行数，则截断状态为真。任何截断信号为真时，Top N 旁必须持续显示“仅当前返回结果”的提示。
- 首个版本中，数据库筛选、聚合和周期对比始终需要新查询，因为当前图表结果不包含经过审核的聚合语义，也不能证明数据覆盖了所需业务范围。
- 当前查询/图表产物仅提供字段名和类型，没有可信单位元数据。因此只有在上下文增加可信单位元数据，或用户明确指出相关度量的源单位和目标显示单位时，才允许单位换算。仅说“改成万元”有歧义，必须询问源单位。摘要要明确显示用户声明的源单位；模型不得根据字段名、数值或示例推断单位。
- 固定 `ChartPaletteToken` 映射到柱状图/折线图度量系列，也支持在饼图上按类别分别设置切片颜色。V1 token 为 `blue`、`teal`、`green`、`amber`、`orange`、`red`、`purple`、`slate`，renderer 将其映射为固定颜色值。类别配色操作使用用户指令中的类别显示标签，每次最多八项；Web 仅在当前饼图结果中找到唯一、完全匹配的可见标签时，才解析为类别值并应用。缺失或多个类型化类别值产生相同显示标签时，分别提示类别不在结果中或要求用户消除歧义。同一意图对同一类别给出不同颜色时整体澄清，不得部分应用。不得将查询行/类别值列表发送给解释端点；不得接受任意 CSS/颜色字符串。饼图类别配色仅在现有饼图规则通过时可用，未配置类别使用固定默认调色板。
- `ChartViewConfiguration` 中的饼图类别颜色按当前 `dimension_field` 和类别类型化身份存储，不能只以显示标签作为持久化 key（例如字符串 `"1"` 与数值 `1` 必须区分）。改变维度字段时清除旧维度的类别颜色并在摘要中说明；回放和撤销仍绑定原查询结果。
- 模型可以识别歧义，但由确定性代码判定操作是否本地支持或需要查询。

## 失败行为与安全

- 解释器超时、provider 不兼容、结构化输出格式错误或 schema 校验失败时，返回有界、安全的错误/重试响应，图表保持不变。结构化输出不支持时不得静默降级为约束更弱的解析器。
- 补丁引用不存在的字段、不支持的类型、重复输出字段或无效单位时，必须 fail closed。
- 客户端提供的图表上下文只能用于解释展示编辑指令，不能授予数据源访问权限或授权查询。
- 查询执行必须经过普通认证聊天链路，以及现有访问控制、查询门禁、规划流程和只读查询检查。
- 不接受模型生成的 ECharts 选项、JavaScript、CSS 字符串或 SQL。

## 首个版本不包含

- 本地按月聚合、同比/周期对比、目标线或因果分析。
- 自动推断度量聚合语义或未知源单位。
- 跨设备的服务端图表 override 和撤销历史持久化。
- 撤销或补偿已完成的数据库查询。

## 验收标准

1. 单纯展示编辑指令只更新图表，不启动聊天 turn 或查询。
2. 界面展示准确的变更摘要，“撤销”可恢复上一个视图。
3. 手动编辑器和自然语言编辑使用相同的校验及持久化操作。
4. 未知字段/类别、类别显示标签歧义、未知源单位、格式错误的意图和不支持的图表类型均不修改已保存视图。
5. 当前结果 Top N 明示范围；结果截断时明确提示其不是全量排名。
6. 数据库筛选、按月聚合、同比和全量 Top N 均先显示查询提议，只有用户确认后才执行。
7. 查询失败时源图表及其配置保持不变。
8. 图表编辑端点不绑定查询或图表渲染工具，且不接收 SQL 或查询行。
9. 不支持结构化输出的 provider 必须 fail closed，且不能影响 `/v1/chat`；记录每个启用的模型/provider 配置的兼容性。
10. 未授权、未绑定、线程所有者不匹配、数据源不匹配/禁用、模型配置无效的请求都必须在解释前失败；每条已获取的 lease 在所有退出路径都释放。
11. 需要查询的确认流程通过常规认证路由发送界面预览的自然语言消息，触发现有图表请求行为，且不转发解释器生成的 SQL/查询文本。
12. 混合编辑只在确认后的 turn 成功、查询和图表结果 ID 一致且字段兼容时应用；错误、取消、无图表、ID 不匹配或字段不兼容时保留原图并丢弃暂存状态。
13. 缓存写入失败、结果淘汰/过期、无效 override 或撤销失败时，当前视图/历史保持一致，撤销记录不能被应用到其他源结果。
14. Top N 使用可见且已选中的数值字段、1–100 范围、稳定并列顺序和前 1,000 条返回行；任一截断信号存在时持续显示截断提示。
15. 饼图类别配色只接受固定 palette token，并以当前结果中唯一匹配的类别为目标；未知或显示名冲突的类别不能部分应用，任一失败均不修改视图。

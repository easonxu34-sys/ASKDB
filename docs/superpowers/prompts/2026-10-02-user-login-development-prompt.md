## 已批准的产品和架构边界

- 单组织、多用户、本地账号；没有 SSO/IdP，不允许自助注册。
- 用户用管理员分配的用户名或工号登录。部署人员通过 Agent 主机上的一次性初始化流程创建首位管理员；之后由管理员创建账号。
- 新账号和管理员重置账号时生成只展示一次的临时密码；首次登录强制改密。不得存储或记录明文密码/临时密码。
- `admin` 管理账号、模型和数据源，也可以聊天，并可访问全部已启用数据源；`member` 只能聊天，并且只能访问管理员分配给自己的数据源。
- Agent 是身份、角色、会话和数据源授权的权威方。Next.js BFF 只管理浏览器 Cookie、CSRF 检查和请求转发；不得信任浏览器提交的 `user_id`、角色、身份 header 或 `data_source_id` 作为授权证明。
- Demo 首期按单 Agent 实例和现有 `ASKDB_SETTINGS_DB_PATH` SQLite 文件设计；若存储不可用，受保护功能失败关闭，不退回匿名模式。
- 会话记忆正文、摘要和个人记忆不在本功能实现。只建立可信 `user_id`/principal 和 thread owner 校验接口，供后续按 `docs/Agent记忆体系设计.md` 实现记忆系统。
- 旧未登录 thread 不自动归属给首个登录用户，不迁移到用户空间；旧浏览器 localStorage 数据保留但不显示在认证会话列表中。新本地 thread 按稳定 `user_id` 隔离。
- 当前 Demo 阶段不实现 TOTP/MFA、OIDC/SSO、邮件找回、自助注册、行级或表级权限、多实例运行。

## 收到“可以 执行”之后

按获批的计划逐片交付端到端功能，不以隐藏 UI 代替 Agent 授权。至少落实以下安全不变量：

1. 使用 Argon2id 存密码哈希；新设密码只校验至少 8 个字符，不额外要求大小写、数字、符号或密码黑名单；密码输入默认掩码并提供显示/隐藏按钮，但首次登录强制改密时的临时密码字段保持掩码且不提供切换；失败限流、通用登录错误、session token 哈希、30 分钟 idle 和 8 小时 absolute 超时按设计文档执行。
2. session token 由 Agent 生成和持久化哈希；浏览器只通过 `HttpOnly; Secure; SameSite=Lax; Path=/` Cookie 持有原 token。BFF 只在服务端转发 token，不把它放入 JSON、localStorage、SSE、URL 或日志。
3. 登录、退出、`/me`、改密、用户管理、数据源授权和安全模型选择路由按设计文档的 API 矩阵实施。每个现有 Agent 路由都要明确匿名、admin、member 的策略；不可遗漏旧路由。
4. Agent 每个受保护请求重新读取会话、账号状态、角色和数据源授权。退出撤销当前 session；账号禁用、密码重置和角色改变撤销该用户所有 session；数据源撤权对下一请求立即生效。
5. Thread 第一次绑定时，Agent 使用可信 principal 原子保存 `owner_user_id` 和数据源。后续请求验证 thread owner 与数据源授权；不能凭 `thread_id` 恢复身份或更换数据源。旧 owner 为空的 thread 拒绝续用并要求新建。
6. 所有管理写操作只能由 Agent 授权的 admin 执行；普通用户只获得当前用户可用的数据源列表和供聊天选择模型的无凭据 projection。
7. 临时密码、密码、Cookie/session token、模型 API Key、数据源 secret 和聊天正文不写入普通日志、错误响应或浏览器持久存储。
8. 新增配置必须遵循子项目现有结构和本地 `AGENTS.md`。写 Web 代码前按 `askdb-web/AGENTS.md` 要求阅读当前安装版本的 Next.js 本地文档。保持现有 FastAPI、LangGraph、Wren、聊天请求和 SSE 契约兼容，除非获批设计明确要求变化。

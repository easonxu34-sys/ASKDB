## 1. 开工要求

- 检查当前分支、worktree 和 `git status`，记录并保护已有修改。使用当前用户选定的工作区，不自行换 worktree。
- 沿真实调用链阅读 Web → Next.js BFF → FastAPI → Application → Agent/Wren。不要按旧文档重新迁移 SQLite；当前 PostgreSQL 已是应用数据库，迁移器也已支持增量版本，以实时源码为准。
- 先给简短的实现顺序说明，然后继续开发。仅对真实缺失且无法合理决定的事项询问，独立工作继续推进。
- 默认由主 Agent 直接实现，不自行创建新聊天或并行子 Agent。
- 不自动提交、推送、创建 PR、部署、重启运行中的用户服务或执行真实业务查询。
- 不读取、修改、暂存或提交 `askdb-server/askdb-admin/src/main/resources/application.yml`；不打印 `.env`、API Key、数据库 DSN 或解密后的凭据。

## 2. 第一版必须完整交付

交付一条完整链路：个人开关 → 聊天明确保存/更新/忘记 → PostgreSQL 持久化 → 后续会话召回 → 本轮应用 → 页面管理。

### 2.1 开关与写入

- 管理员和普通用户都有自己的开关，按可信 `Principal.user_id` 隔离，默认关闭。
- 开启后仅在用户明确表达长期意图时保存，例如“记住”“以后都这样”“下次也这样”。普通聊天和“这次简短一点”不自动成为长期记忆。
- 清楚的保存请求直接处理，不重复弹确认；指代不清时才澄清。只有数据库持久化成功才回复“已记住”。
- 关闭后停止聊天保存/更新和个性化召回，已有记录保留；重新打开恢复使用。
- 关闭状态仍允许聊天明确忘记，属于管理操作，不自动开启开关。定位删除目标可读取本人有界候选，不能将其用于个性化回答。页面显式管理仍允许。
- 当前回答使用开始时的读取快照，修改/删除/关闭对回答从下一轮生效。
- 关闭取消尚未提交的聊天保存/更新，已提交记录保留。用 settings 行锁与 write_epoch 防止“关闭后又打开”使旧提取任务继续保存；取消写入不取消当前回答。

### 2.2 六类内容与使用行为

| 类别 | 必须实现的行为 |
|---|---|
| 表达偏好 | 语言、称呼、回答组织等在相关回答中使用 |
| 展示偏好 | 单位、图表等在数据条件允许时应用，未知单位不猜测转换 |
| 操作习惯 | 本次问题需要时采用分析步骤，不额外展开简单问题 |
| 常用范围 | 自动采用默认筛选，并明确显示；本轮明确范围优先 |
| 个人业务定义 | 优先使用个人口径并显示，绑定到可验证的指标/字段，不修改共享 MDL |
| 分析方法 | 保存步骤、默认条件和展示方式，下次根据当前问题与最新数据重新执行 |

- 表达/展示默认全局；步骤、筛选、个人口径和方法默认当前数据源。用户明确说所有数据源适用时再扩大；各源分别校验绑定。
- 用户问“销售额是多少”就按需直接回答；问“分析销售情况”时才采用完整方法。
- 相对时间保留规则并在下次重新计算；明确绝对日期保持固定。
- 保存“刚才的方法”应依据成功执行的有界分析元数据。现有历史若只有助手文本，补充最小成功分析描述存储；不保存结果行/完整 SQL，不凭话术猜已执行步骤。
- 同范围同场景的新要求自动替代旧冲突项，并告知；不同场景并存。多个匹配会影响指标、范围或步骤时先简短澄清。
- 默认长期有效；用户指定期限时按期停止使用。
- 删除来源会话不删除已经保存的记忆。明确忘记一条直接删除，模糊目标先询问，清空全部一次确认。

## 3. 模型配置与云服务

- 扩展现有 Web 模型配置页，新增 `Chat / Embedding / Rerank` 类型；已有记录迁移为 Chat。
- 第一版 Embedding/Rerank 接入阿里云百炼（通义千问），在 Web 配置模型、地址、密钥和所需参数，不放在 Agent `.env` 中作为业务配置。
- 模板可采用 `text-embedding-v4`、1024 维和 `qwen3-rerank`，具体模型/地址可配置。实现前核对当前官方协议和地域地址，不把模型名当 API 协议，不把 Rerank 请求套成 Chat 请求。
- 类型分别测试连接和返回结构：Embedding 校验有限数值/维度/顺序；Rerank 校验候选 index/唯一性/边界。
- 按类型维护唯一默认值，记忆直接引用默认 Embedding/Rerank；管理员另行指定记忆处理 Chat 模型，不跟随用户会话模型变化。
- 会话、图表意图解释及其他 Chat 消费方仅允许 Chat。同步检查 Agent schema、model store/application、BFF 白名单投影、前端类型和选择器，避免新字段被丢弃。
- API Key 沿用 Fernet 加密，仅返回已配置状态。删除正在被引用的配置先要求替代项；保留既有默认 Chat 接口兼容性。

## 4. 存储、检索与更新

- 使用 PostgreSQL + pgvector + BM25 + 云 Embedding + 本地 RRF + 云 Rerank，第一版不推迟整个检索功能。
- 固定表达配置、默认筛选、个人口径不能只靠向量 Top-K，避免漏召回使查询无提示变宽或采用错误口径。
- 外部调用前先按 owner/source/权限过滤候选；本轮只使用自己的快照内容，版本和条件一致才采用。
- 云检索失败先降级结构化记录和 BM25；仍无法确定相关范围/口径时询问是否按当前问题继续，不静默绕过记忆。
- 开关或记忆存储读取失败不能当作正常关闭/无记忆；本轮明确同意不用记忆不改变永久开关，也不取消正常权限/语义校验。
- 保存与索引任务在同一事务登记，模型调用在事务外进行；job 返回后核验版本、hash、删除状态和 generation，不让迟到任务复活旧记录。
- Embedding 空间改变使用新 generation 重建并切换，保留旧配置版本的解析能力，不以新模型查询旧向量。Rerank 切换不要求向量重建。
- 初版可按 owner/generation 严格过滤后精确向量搜索，不先设计大型 ANN/多服务集群。
- 复用删除日志与 suppression 能力，补全 global/owner 范围；删除中途失败可重放，旧索引/备份不能复活删除或被替代内容。
- 采用简洁数据结构；技术设计里的表是逻辑职责，可以合并 JSONB 和 operations，不机械建立八张表，不引入额外队列服务/通用工作流框架。
- 新增增量迁移使用当前下一个空闲编号，不修改已应用文件 checksum；若 pgvector 不可用，给出准确安装/启用说明，不擅自修改系统数据库或安装全局服务。

## 5. 查询与聊天接入边界

- 明确的记忆管理请求独立于数据 Query Gate，纯管理不执行查询工具；在合法会话与授权校验后尽量先于查询 runtime lease 获取。
- 私有指标解释由受限绑定进入本轮上下文，不作为任意高优先级指令，不写入共享 runtime、共享 MDL 或业务规则语料。
- 实际查询继续现有 `validate_read_query → dry_plan → dry_run → query`。复用已有 SQLGlot/计划信息核对可明确识别的个人条件/指标；无法确定时澄清，不只靠提示词就声称已按个人口径执行。
- 不新增通用 SQL 等价证明器、复杂语义门禁或额外人工审批。
- 图表只用本轮成功查询结果，显示偏好不修改原始结果，不为套偏好执行未经本次问题需要的额外分析。
- 个人记忆计入实际上下文预算；可选偏好可裁剪，必要范围/口径不能静默丢弃后执行。
- 纯管理、混合查询、澄清、异常、取消路径都保持 turn 完成/失败及 lease finally 释放。混合请求查询成功但保存失败时分别说明，重试不重复动作。
- 确认请求采用服务端 request_id/choice_id，绑定 owner/thread/source/目标版本/期限，一次性消费；不由模型猜一句“是”同意了哪些删除。

## 6. 页面与反馈

- 新增 `/settings/preferences`：开关、记忆列表、类型、范围、期限、编辑、删除、清空和错误重试。管理员默认无权浏览其他人的私有记忆。
- 沿用 SettingsShell/SettingsPageHeader，所有单值下拉使用 ComposerSelect。修改前读取相关版本的本地 Next.js 文档。
- 页面明确区分：回答下一轮采用新状态；关闭立即阻止未提交保存。失败保留草稿，账号切换清掉旧账号页面状态。
- Web 仅访问同源 BFF，复用认证 Cookie、CSRF 和 no-store。后台服务、云密钥不能暴露给浏览器。
- 保存、更新、删除反馈由真实结果生成；使用提示区分模型收到偏好与实际应用的范围/指标/展示。不展示内部提取 trace 或空状态卡。
- 新 SSE 事件同步更新 application、编码器、BFF、客户端适配器及历史刷新状态，不破坏现有业务记忆提示。

按以下顺序连续完成，无需每一步重复等待批准：

1. 三类模型 schema/存储/API/BFF/页面与调用方过滤。

3. 专用模型保存/更新/忘记和成功分析来源描述。
4. pgvector、索引任务、BM25/RRF/Rerank 与模型空间切换。
5. 本轮范围/口径解析、分析方法、显示与澄清。
6. 串联混合请求、故障降级、操作反馈并交付。

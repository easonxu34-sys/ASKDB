# T3 Web implementation prompt

**目标：**完成 T3 记忆候选在 AskDB 网页中的提交、跟踪和管理员治理流程，并修正 Web 接入暴露出的 API 契约问题。

**设计依据：**[记忆体系设计](../plans/2026-10-02-agent-memory-system.md) 中的 T3A、T3B、T3C、T3 Web UX 与 T4 边界；[T3A/T3B/C 通用实现提示词](2026-10-02-agent-memory-implementation-prompts.md)。发生冲突时暂停并报告，不另造状态机或更改现有 SQL/Wren 安全链路。

## 当前代码状态

- Agent 已注册 `/v1/query-examples`、`/v1/business-rules` 路由，候选管理和发布状态由服务端持有。先核对现有接口，不重复实现后端能力。
- Web 已有 Next.js BFF 会话认证、Bearer 转发、CSRF、请求体白名单及 `no-store` 模式；按既有代理边界接入。
- Web 聊天已经把成功查询结果作为本地结果 artifact 展示；查询示例只能从成功查询的回答提交，不能把结果行或具体参数值发送到候选接口。Agent 在持久化前还必须用 SQL AST 拒绝 WHERE/HAVING 中硬编码的筛选常量；页面勾选不能替代服务端校验。
- **契约待核对：**查询示例 schema 目前将 `source_turn_id` 定义为 UUID，但聊天线程历史暴露的是不透明逻辑 turn key，持久化表同时另有 UUID 行 ID。提交 UI 前先按代码确定权威引用方式；若需修改，采用服务端从 `thread_id + logical turn key` 解析出持久化行 ID，并校验该 turn 已完成、属于该线程，不信任客户端传来的 DB 行 ID。
- 工作区位于 `main`，已有用户未提交改动：`askdb-agent/src/agent/presentation.py`、`askdb-agent/src/agent/prompts.py`、`askdb-web/components/ui/composer-select.tsx`。保留它们，不回退、不覆盖、不顺手格式化。

## 实施顺序

1. 审核查询示例提交的 turn 来源引用；只改完成来源校验所需的 Agent schema/application/store/路由接口。
2. 为查询示例、业务规则的提交、本人列表、候选审核/撤回/发布/撤销及操作状态增加窄范围 Next BFF 路由。延续 Bearer 会话、CSRF、严格字段白名单、大小限制、上游错误映射和 `no-store`。
3. 在助手回答的“…”菜单加入记忆提交入口。查询示例只在成功查询回答中出现；表单预填问题及 SQL 模板和类型占位符，允许用户检查/编辑，明确不发送参数值、结果行或整段对话。提交前由 Agent 用 SQL AST 拒绝 WHERE/HAVING 中硬编码的筛选值，必须改成命名参数。业务规则表单只收集术语、定义和可选模型/字段引用，不提交整段对话。
4. 增加“我的提交”视图及管理员“记忆管理”页。展示查询示例、业务规则、数据源筛选、审核状态和生效/发布状态；只有管理员可执行审核、发布、激活、撤销等管理动作。审核通过和已生效必须分开展示。
5. 根据真实 API 返回值映射状态和错误；处理载入、空列表、无权、冲突/语义过期、限额、可重试失败。未提交的表单内容遇到请求失败时保留。
6. 更新 T3 进度记录，写明实际改动、静态检查结果和未验证项。

## 硬边界

- 不实现个人偏好/姓名记忆；不把截图里的个人问答存成业务规则。
- 不把审核成功说成记忆已生效。查询示例需要独立语料激活；业务规则需要独立 Wren 发布。
- 权限和数据源授权始终由 Agent 服务端校验；Web 隐藏控件不构成权限边界。
- 不编辑 T4 所有的运行时协调代码，除非实际集成暴露明确阻塞并先报告。
- 本任务未要求新增或运行自动化测试；不添加/运行测试。保留既有静态检查，并准确报告检查未覆盖的行为。
- 串行在当前工作区实现；不启动子 agent、不建分支/工作树、不提交 Git。所有改动完成后逐文件检查差异，确认上述用户改动原样保留。
